## Technical-readme.md

On MST2 basically the whole cockpit UI sits in one file, `MIBHMI.jxe`, packed inside a container called `tsd.mibstd2.hmi.ifs`. You can unpack and repack that container with IFSTool. The jxe itself isnt a normal jar, its built for the old IBM J9 java machine and holds almost the entire MIB interface. Theres barely any tooling for jxe files, but luckily a set of utils called JXETools lets you pull the bytecode of the classes you want and decompile them with normal java tools. Finding the right classes wasnt too bad since they line up almost 1:1 with the ones from MHI2.

The classic route from there would be to recompile the classes, build them back into a jxe and pack that into the ifs. Problem is the risk is huge, one small mistake at that stage and the whole UI is dead and you brick the unit. So instead we dont touch `MIBHMI.jxe` or `tsd.mibstd2.hmi.ifs` at all. The java machine is started by a bash script at `/tsd/hmi/runHMI.sh`, and that one we CAN edit. The trick (credit to andrewleech) is to compile only the classes you need into a small separate jar and tell the VM to load it with priority (`-Xbootclasspath/p:`). The stock files stay exactly as they are so the risk stays minimal, and if something goes wrong you just remove that one line and youre back to stock.

What our patch actually does: the classes we load first shadow a handful of the stock ones, the ones that draw the now-playing screen. The head unit already gets all the CarPlay info from the iphone (title, artist, album, cover, position, shuffle), it just normally ignores it and never forwards it to the cluster. Our shadowed classes catch that data and actually process it instead, push the text into the VC, feed the cover, build the timer and light up the shuffle icon. Nothing in the firmware gets rewritten, it just loads at boot and can be removed anytime.

MHI2 (all MHI2 testing was done by the cn-tester) works the same in spirit but a fair bit had to change. The filesystem is laid out completely differently, everything sits under `/mnt/app/eso/hmi/` instead of `/tsd`, and the app partition is read-only so it has to be remounted rw and the files written into the HMI guest with `on -f mmx`. The VM isnt started by runHMI.sh but by `lsd.sh`, so thats where the priority-jar line goes. The bigger change is the data source: MHI2 has no `/pps` bus to read from, so instead of polling PPS the bridge hooks straight into the CarPlay DSI service and gets title/artist/album/position/shuffle from its callbacks. Cover comes from the cover-art url that same service hands over plus a small native artwork daemon, since theres no shared-memory tap like on MST2. State and logs live on `/mnt/icab/persistent`. Its CN only for now.
